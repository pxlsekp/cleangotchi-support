Folder access

Check caches, logs and Trash separately in the app's folder-access panel. Approved cache/log folders only need a recheck. For an unapproved folder, use that row's macOS permission action and select the exact cache or log folder.

Trash access does not use a hidden-folder picker. Recheck actual access. If macOS denies it, inspect Full Disk Access for the currently running CleanGotchi app in system privacy settings, then fully quit and reopen the app. You can decline and leave that cleanup feature unused. Granting access does not automatically run cleanup.

Why space may remain after cleanup

Caches and logs are moved to the Trash first. Check the moved items in Finder before emptying it. Emptying the Trash permanently deletes eligible inspected items after confirmation and cannot be undone. The app does not automatically restore items to their original locations.

Records waiting to save

File actions may already have completed. Use the record retry action instead of repeating cleanup. Do not delete the recovery journal to bypass a blocked result. When contacting support, first provide the app version, macOS version, displayed error and steps to reproduce, rather than private full paths or file contents.

Automatic versus manual emptying

Automatic emptying is off by default and must be enabled separately. It uses the selected 10-, 30- or 100-day threshold and waiting period while the app runs. Manual emptying permanently removes inspectable items after confirmation, regardless of that period. The app's Trash size display and manual/automatic emptying cover only the internal Mac Trash. Inspect and empty external SSD or USB Trash in Finder.

Does emptying Trash in Finder also feed the pet?

When CleanGotchi is running and can access the relevant Trash, regular files emptied directly in Finder or the Dock can count as food after deletion is confirmed. It observes the internal Mac Trash (~/.Trash) and the current user's Trash on connected writable local disks (/Volumes/<disk>/.Trashes/<current user UID>), including external SSDs and USB drives. It does not inspect other users' Trash. This does not enable automatic emptying or automatically grant new access permissions, and the observer never deletes files itself. Items recognized as already credited through their cleanup batch or saved file identity are not counted again.

The Trash card shows whether observation is getting ready, covers only some items, or needs permission. Files deleted too quickly before tracking started, while the app was closed, or beyond its access restrictions and limits on simultaneously tracked files and folders may be missed. Restored or moved items, symbolic links, files already having multiple hard links at first observation, and Trash on network or read-only volumes are not counted. Disconnecting a disk does not count as deletion; reconnecting starts fresh observation. Deletions while disconnected and previously deleted files are not credited retrospectively. Food uses the file’s logical size and may differ from the physical disk space released. Manual inspection controls cache/log lists separately from this Trash observation. If an old-version cleanup batch was renamed before this feature recorded its identity, the earlier food credit cannot necessarily be reconstructed from the new name.
